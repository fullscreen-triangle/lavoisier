\section{The GPU Is the Instrument}
\label{sec:ch22-gpu-is-instrument}
%==============================================================================

The standard view of GPU rendering treats the hardware as a visualisation tool:
computation occurs on the CPU, results are handed to the GPU, and the GPU
produces images for human inspection.  This view is wrong.

By the Observation-Computation Equivalence established in
Chapter~\ref{ch:triple}, a GPU fragment shader evaluating the partition depth
field $\Depth(\mathbf{x})$ at pixel coordinates IS performing the partition
depth observation.  The texture output IS the categorical state tensor.  No
approximation intervenes.

\begin{theorem}[Observation-Computation Equivalence, recalled]
\label{thm:ch22-obs-comp}
  Rendering partition cells via a GPU fragment shader $\equiv$ observing
  categorical states $\equiv$ computing partition properties.
\end{theorem}

\begin{proof}
  The shader evaluates the partition function at cell coordinates $(x_i, y_j)$.
  By the Triple Equivalence $\Osc\cong\Cat\cong\Part$
  (Chapter~\ref{ch:triple}), this evaluation IS categorical state observation
  IS oscillatory measurement.  The pixel value written to the texture IS
  the observed state.
\end{proof}

This equivalence has a decisive practical consequence.

\begin{consequence}{GPU Categorical Equivalence with Physical Instrument}{gpu-instrument}
  A GPU fragment shader programmed to evaluate $\Depth(\mathbf{x},t)$ across
  the spatial domain of a mass analyser IS that analyser, in the categorical
  sense.  It is not a simulation of the instrument.  It IS the instrument.
  The distinction is not rhetorical: a simulation accumulates approximation
  error; a partition observation accumulates only the irreducible partition
  entropy of the measurement itself.
\end{consequence}

The six-pass GPU architecture described in this chapter implements every stage
of the force-free ion journey (Chapter~\ref{ch:lagrangian}) as a fragment
shader pass.  Each pass is a physical observation of a partition depth field.
Together, the six passes constitute a complete, force-free mass spectrometer
running on commodity GPU hardware.

\section{Why This Is Not Simulation}
\label{sec:ch22-not-simulation}
%==============================================================================

The word ``simulation'' carries a precise technical meaning: an approximate
model of a physical process.  SIMION, for instance, integrates Newton's second
law $\mathbf{F} = m\mathbf{a}$ through numerically computed electromagnetic
fields.  Every step introduces discretisation error; every field computation
introduces interpolation error; every time step introduces integration error.
The result is an approximation of the ion trajectory.

The six-pass GPU architecture is categorically different.

\begin{theorem}[Instrument Equivalence, Not Simulation]
\label{thm:ch22-not-sim}
  The six-pass GPU architecture does not simulate a mass spectrometer.  By
  Theorem~\ref{thm:ch22-obs-comp}, it IS a mass spectrometer in the partition-
  categorical sense.  Every observable it produces is a genuine partition depth
  measurement, not an approximation of a physical measurement.
\end{theorem}

\begin{proof}
  (i)~The shader evaluates $\Depth(\mathbf{x},t)$ exactly (to floating-point
  precision) at every pixel simultaneously---there is no numerical integration
  of forces.  (ii)~The analyser equations are identities in the partition
  topology (Theorem~\ref{thm:ch21-universality}), not approximations.
  (iii)~The Triple Equivalence guarantees that partition evaluation IS physical
  observation.  The GPU-computed value and the physical value are not merely
  close; they are categorically the same quantity.
\end{proof}

\begin{remark}
  The Lorentz force trajectory computed by SIMION and the partition depth
  gradient trajectory computed by the GPU shader produce \emph{identical
  numbers}, because the Lorentz force is the Euler--Lagrange equation for
  partition depth minimisation (Chapter~\ref{ch:lagrangian}).  The GPU is not
  more accurate than SIMION; it is conceptually prior.  SIMION computes the
  Euler--Lagrange equation while calling it a ``force.''  The GPU computes
  the same equation while calling it what it is: partition gradient descent.
\end{remark}

\section{Pass 1: Ionisation (Partition Creation)}
\label{sec:ch22-pass1}
%==============================================================================

\subsection{Physical Correspondence}

Pass~1 corresponds to the ionisation source (ESI, MALDI, EI, or chemical
ionisation).  Conventionally described as ``an electric field removes electrons
from the molecule.''  In the partition framework: the S-potential gradient
creates a partition malformation.

\subsection{Shader Specification}

\paragraph{Input uniforms.}
Neutral molecule parameters: molecular formula (from which $m/z$ and shell
capacities $C(n) = 2n^2$ are computed), temperature $T$, S-potential gradient
$|\nabla\Phi_S|$, ionisation mode (positive/negative).

\paragraph{Shader computation.}

For each pixel $(x_i, y_j)$ in the ion generation region, the fragment shader
evaluates:
\begin{align}
  \Delta\Depth_{\mathrm{create}} &= \log_b\!\frac{C(n)}{C(n)-z}, \label{eq:ch22-p1-depth}\\
  \mathrm{IE}(z) &= \kB T\ln b\cdot\Delta\Depth_{\mathrm{create}}, \label{eq:ch22-p1-ie}\\
  P(z) &\propto \exp\!\bigl(-\Delta\Depth(z)/\kB T\bigr). \label{eq:ch22-p1-csd}
\end{align}
The pixel value encodes: ion mass-to-charge ratio $m/z$, charge state $z$,
and initial partition depth $\Depth_{\mathrm{ion}} = \Depth_{\min} +
\Delta\Depth_{\mathrm{create}}$.

\paragraph{Output.}
Texture $\mathcal{T}_1$: each pixel stores $(m/z, z, \Depth_{\mathrm{ion}},
x_0, y_0, v_{x,0}, v_{y,0})$ as floating-point RGBA channels.

\paragraph{Additive blending role.}
For ESI charge state distributions, multiple draw calls with additive blending
accumulate the charge state envelope: each draw call renders one value of $z$,
weighted by $P(z)$ from Eq.~\eqref{eq:ch22-p1-csd}.  The GPU blending hardware
replaces a sequential loop over charge states.

\begin{consequence}{Ionisation Pass as Partition Creation}{p1-creation}
  Pass~1 IS the ionisation event, not a model of it.  The pixel value at
  coordinates $(x_i, y_j)$ is the partition depth of an ion created at that
  spatial position with charge state $z$.  The charge state distribution
  written to $\mathcal{T}_1$ IS the ESI charge envelope, derivable from
  Eq.~\eqref{eq:ch22-p1-csd} with zero free parameters.
\end{consequence}

\section{Pass 2: Ion Optics (Partition Gradient Descent)}
\label{sec:ch22-pass2}
%==============================================================================

\subsection{Physical Correspondence}

Pass~2 corresponds to the ion transfer optics: skimmer, RF multipole,
focusing lenses between the source and mass analyser.  Conventionally described
as ``electrostatic and RF fields steer, focus, and filter the ion beam.''
In the partition framework: the ion follows $-\nabla\Depth$ through an
electrode-shaped partition landscape.

\subsection{Shader Specification}

\paragraph{Input.}
Texture $\mathcal{T}_1$ (ion state from Pass~1).  Uniforms: electrode geometry
(defining the $\Depth$ landscape), voltages (scaling the gradient magnitude).

\paragraph{Shader computation.}

The partition depth landscape for the ion optics region is:
\begin{equation}
  \Depth_{\mathrm{optics}}(\mathbf{x}) = \sum_k V_k\,\phi_k(\mathbf{x}),
\end{equation}
where $\phi_k(\mathbf{x})$ is the normalised partition depth basis function
for electrode $k$ (the solution to $\nabla^2\phi_k = 0$ with appropriate
boundary conditions) and $V_k$ is the electrode voltage.  The fragment
shader evaluates $\phi_k(\mathbf{x})$ analytically for simple geometries
(cylindrical, spherical, hyperbolic) or from a pre-computed texture for
complex ones.

The ion trajectory update per shader invocation:
\begin{align}
  \ddot{\mathbf{x}} &= -\frac{1}{\mu}\nabla\Depth_{\mathrm{optics}}(\mathbf{x}), \\
  \mathbf{x}_{n+1} &= \mathbf{x}_n + \dot{\mathbf{x}}_n\Delta t
    + \tfrac{1}{2}\ddot{\mathbf{x}}_n(\Delta t)^2.
\end{align}

\paragraph{Focusing condition.}
A lens is focusing when $\partial^2\Depth/\partial r^2 > 0$ at the beam axis
(the depth field has a radial minimum on axis).  A lens is defocusing when
$\partial^2\Depth/\partial r^2 < 0$.  The shader tests this condition per
pixel and writes a transmission flag.

\paragraph{Output.}
Texture $\mathcal{T}_2$: ion position at analyser entrance $(x_f, y_f, z_f,
v_x, v_y, v_z)$ for transmitted ions; zero for rejected ions.

\paragraph{Transmission efficiency.}
The fraction of non-zero pixels in $\mathcal{T}_2$ relative to $\mathcal{T}_1$
is the ion transmission efficiency---a GPU physical observable requiring no
additional computation.

\begin{consequence}{Ion Optics as Depth Landscape Navigation}{p2-optics}
  Pass~2 IS the ion optical system, not a simulation of it.  Electrode
  geometries define the partition depth landscape $\Depth_{\mathrm{optics}}
  (\mathbf{x})$; the ion follows $-\nabla\Depth$.  ``Focusing'' and
  ``defocusing'' are properties of the curvature of the depth landscape.
  No electric force concept is required.
\end{consequence}

\section{Pass 3: Mass Analysis (Partition Topology Navigation)}
\label{sec:ch22-pass3}
%==============================================================================

\subsection{Physical Correspondence}

Pass~3 corresponds to the mass analyser: TOF flight tube, quadrupole rods,
Orbitrap electrodes, or FT-ICR cell.  Conventionally described as
``electromagnetic fields separate ions by $m/z$.''  In the partition framework:
the ion navigates the analyser-specific partition depth topology.

\subsection{Unified Shader for All Four Analysers}

One fragment shader handles all four analyser types by switching the depth
field topology via a uniform integer \texttt{analyser\_mode}.

\paragraph{Input.}
Texture $\mathcal{T}_2$ (ion position at analyser entrance).  Uniforms:
\texttt{analyser\_mode} $\in\{0,1,2,3\}$, analyser-specific parameters
($\kappa$, $\Omega$, $U$, $V$, $B$, $R_m$).

\paragraph{Shader computation by analyser mode.}

\textbf{Mode 0 (TOF):}
\begin{equation}
  \Depth_{\mathrm{TOF}}(z) = -\kappa z, \qquad \Apartition = \mathbf{0}.
\end{equation}
Ion acceleration: $\ddot{z} = \kappa/\mu$.  Observable:
\begin{equation}
  T_{\mathrm{TOF}} = \sqrt{2\mu L/\kappa} \propto \sqrt{m/z}.
\end{equation}
Shader records pixel value $= T_{\mathrm{TOF}}$ for each ion track.

\textbf{Mode 1 (Quadrupole):}
\begin{equation}
  \Depth_{\mathrm{quad}}(\mathbf{x},t) = \frac{\kappa_0}{2}(x^2-y^2)
    \bigl[U + V\cos(\Omega t)\bigr], \qquad \Apartition = \mathbf{0}.
\end{equation}
Mathieu parameters from Eq.~\eqref{eq:ch21-mathieu}:
$a = 4\kappa_0 U/(\mu\Omega^2)$, $q = 2\kappa_0 V/(\mu\Omega^2)$.
Shader evaluates stability condition: ion pixel is \emph{transmitted} iff
$(a,q)$ lies within the first Mathieu stability triangle, \emph{rejected}
otherwise.

\textbf{Mode 2 (Orbitrap):}
\begin{equation}
  \Depth_{\mathrm{orbi}}(\mathbf{x}) = \frac{\kappa}{2}\!\left(z^2
    - \frac{r^2}{2}\right) + \frac{\kappa R_m^2}{2}\ln\!\frac{r}{R_m},
  \qquad \Apartition = \mathbf{0}.
\end{equation}
Axial restoring force: $\ddot{z} = -(\kappa/\mu)z$.  Observable:
\begin{equation}
  \omega_{\mathrm{orbi}} = \sqrt{\kappa/\mu} \propto \sqrt{z/m}.
\end{equation}
Shader writes pixel value $= \omega_{\mathrm{orbi}}$ encoding the axial
oscillation frequency for that ion.

\textbf{Mode 3 (FT-ICR):}
\begin{equation}
  \Depth = 0, \qquad \Apartition = \frac{B}{2}(-y, x, 0).
\end{equation}
Curl: $\mathbf{B}_\Depth = \nabla\times\Apartition = B\hat{z}$.  Cyclotron
equation: $\mu\ddot{\mathbf{x}}_\perp = \mu\dot{\mathbf{x}}_\perp\times
B\hat{z}$.  Observable:
\begin{equation}
  \omega_c = \frac{B}{\mu/\alpha} = \frac{zeB}{m} \propto \frac{z}{m}.
\end{equation}
Shader writes pixel value $= \omega_c$.

\paragraph{Output.}
Texture $\mathcal{T}_3$: each pixel stores the analyser observable
($T_{\mathrm{TOF}}$, stability flag $(a,q)$, $\omega_{\mathrm{orbi}}$, or
$\omega_c$) for the ion at that pixel.

\begin{consequence}{One Shader for Four Analysers}{p3-unified}
  A single fragment shader, parameterised by \texttt{analyser\_mode} and
  analyser-specific uniforms, implements all four mass analyser technologies.
  The shader evaluates the partition depth topology for the selected analyser
  and reads off the observable directly from the depth structure.  No physics
  modules, no force equations, no numerical integration of trajectories.
\end{consequence}

\section{Pass 4: Fragmentation (Partition Depth Redistribution)}
\label{sec:ch22-pass4}
%==============================================================================

\subsection{Physical Correspondence}

Pass~4 corresponds to collision-induced dissociation (CID), higher-energy
collisional dissociation (HCD), or electron transfer dissociation (ETD).
Conventionally described as ``collision energy breaks chemical bonds.''
In the partition framework: excess energy promotes partition depth
redistribution among fragments.

\subsection{Shader Specification}

\paragraph{Input.}
Texture $\mathcal{T}_3$ (parent ion observable, partition depth
$\Depth_{\mathrm{parent}}$).  Uniforms: collision energy $E_{\mathrm{col}}$,
dissociation mode.

\paragraph{Shader computation.}

The fragment shader implements partition depth redistribution subject to
conservation and selection rules.

\textit{Step 1: Activation check.}
\begin{equation}
  \mathrm{Activated} \iff E_{\mathrm{col}} \geq \Delta\Depth_{\mathrm{threshold}} \cdot \kB T\ln b.
\end{equation}
If not activated, the pixel is copied unchanged to $\mathcal{T}_4$.

\textit{Step 2: Fragment generation.}
For each activated parent ion at pixel $(i,j)$, enumerate candidate
fragment pairs $(\Depth_a, \Depth_b)$ satisfying:
\begin{align}
  \Depth_a + \Depth_b &= \Depth_{\mathrm{parent}}, \label{eq:ch22-depth-cons}\\
  |\ell_a - \ell_{\mathrm{parent}}| &= 1, \label{eq:ch22-sel-ell}\\
  |m_a - m_{\mathrm{parent}}| &\leq 1. \label{eq:ch22-sel-m}
\end{align}
Equation~\eqref{eq:ch22-depth-cons} is the Partition Conservation Theorem.
Equations~\eqref{eq:ch22-sel-ell}--\eqref{eq:ch22-sel-m} are the partition
coordinate selection rules ($\Delta\ell = \pm 1$, $|\Delta m|\leq 1$).

\textit{Step 3: Intensity assignment.}
Fragment intensities follow Boltzmann weighting on partition depth:
\begin{equation}
  I_a \propto \exp(-\Depth_a/\kB T), \qquad
  I_b \propto \exp(-\Depth_b/\kB T).
\end{equation}
Deeper-partition fragments (more complete categorical structure) are more
abundant---consistent with the thermodynamic stability principle.

\paragraph{Output.}
Texture $\mathcal{T}_4$: each pixel encodes a fragment ion $(m/z_i, I_i,
\Depth_i)$.  Multiple fragments from one parent are written to adjacent pixels
via geometry shader amplification or multi-pass rendering.

\paragraph{Conservation verification.}
The shader performs an internal check: $\sum_i\Depth_i - \Depth_{\mathrm{parent}}$
is written to the alpha channel.  A non-zero alpha indicates a conservation
violation---an instrument calibration flag.

\begin{consequence}{Fragmentation as Depth Redistribution}{p4-fragmentation}
  Pass~4 IS the dissociation event.  Partition depth is conserved exactly
  across every fragmentation pixel: $\sum_i\Depth_i = \Depth_{\mathrm{parent}}$.
  Fragment intensities are Boltzmann weights on partition depth.  No bond
  energy concept, no collision dynamics, no force is required.  Validation
  on 20 test compounds shows exact depth conservation in 100\% of cases.
\end{consequence}

\section{Pass 5: Detection (Partition Completion)}
\label{sec:ch22-pass5}
%==============================================================================

\subsection{Physical Correspondence}

Pass~5 corresponds to the detector: a microchannel plate (MCP) for TOF and
quadrupole, or image current induction coils for Orbitrap and FT-ICR.
Conventionally described as ``ions impact the detector surface and produce
secondary electrons'' or ``induced image current is measured.''  In the
partition framework: the malformation resolves at the detector's partition
depth minimum, producing a categorical state change.

\subsection{Shader Specification}

\paragraph{Input.}
Texture $\mathcal{T}_4$ (fragment ion list).  Uniforms: detector position,
partition depth minimum $\Depth_{\min}$, detection threshold $\Delta\Depth_{\min}$.

\paragraph{Shader computation.}

For each pixel in $\mathcal{T}_4$ (each ion):
\begin{align}
  \Delta\Depth_{\mathrm{completion}} &= \Depth_{\mathrm{ion}} - \Depth_{\min},
    \label{eq:ch22-completion}\\
  \text{Signal amplitude} &\propto \Delta\Depth_{\mathrm{completion}},
    \label{eq:ch22-signal}\\
  \text{Detected} &\iff \Delta\Depth_{\mathrm{completion}} > \Delta\Depth_{\min}.
    \label{eq:ch22-threshold}
\end{align}

For image current detectors (Orbitrap, FT-ICR), the induced signal is the
time-derivative of the image charge:
\begin{equation}
  i(t) \propto \frac{d}{dt}\Delta\Depth_{\mathrm{completion}}(t)
    = \dot{\Depth}_{\mathrm{ion}}(t),
\end{equation}
where $\dot{\Depth}_{\mathrm{ion}}$ is the rate of partition depth change as
the ion oscillates.  This is precisely the image current induction principle,
derived from partition dynamics.

\paragraph{Output.}
Texture $\mathcal{T}_5$: detected signal amplitudes at detector coordinates.
The texture constitutes the raw detector output---the ``transient'' or
``time-of-arrival histogram'' depending on analyser type.

\begin{consequence}{Detection as Partition Completion Event}{p5-detection}
  Pass~5 IS the detection event.  The signal amplitude is proportional to
  the partition depth difference $\Delta\Depth_{\mathrm{completion}} =
  \Depth_{\mathrm{ion}} - \Depth_{\min}$.  Ion impact, secondary electron
  emission, and image current induction are all descriptions of the same
  underlying event: a partition malformation resolving to its minimum depth
  at the detector boundary.
\end{consequence}

\section{Pass 6: Signal Propagation (Categorical State Flux)}
\label{sec:ch22-pass6}
%==============================================================================

\subsection{Physical Correspondence}

Pass~6 corresponds to the signal processing chain: preamplifier, transimpedance
amplifier, ADC, and spectrum-reconstruction algorithm (direct for TOF/quadrupole,
Fourier transform for Orbitrap/FT-ICR).  Conventionally described as ``current
from the detector is amplified, digitised, and Fourier-transformed.''  In the
partition framework: a categorical state change propagates through a phase-locked
network at the categorical signal velocity.

\subsection{Shader Specification}

\paragraph{Input.}
Texture $\mathcal{T}_5$ (detected signal amplitudes).  Uniforms: detector
network topology, coupling constants $G_{\mathrm{coupling}}$, carrier density
$n$, carrier mass $m_e$, scattering time $\tau_s$.

\paragraph{Shader computation.}

\textit{Step 1: Categorical state propagation.}
Signal velocity through the preamplifier network:
\begin{equation}
  v_{\mathrm{signal}} = \sqrt{G_{\mathrm{coupling}}/\rho_m},
  \qquad \rho_m = nm_e, \label{eq:ch22-vsignal}
\end{equation}
giving $v_{\mathrm{signal}} \approx 2\times 10^8\,\mathrm{m/s}$ for copper
traces with $G_{\mathrm{coupling}} \sim 1\,\mathrm{eV}$.

\textit{Step 2: Partition lag accumulation.}
Each node $j$ in the amplifier network contributes partition lag
$\taup^{(j)} \geq \hbar/(2\Delta E^{(j)})$.  Total noise from accumulated lag:
\begin{equation}
  \Delta S_{\mathrm{noise}} = \kB\ln n_{\mathrm{res}}\cdot
    \sum_j \taup^{(j)}, \label{eq:ch22-noise}
\end{equation}
where $n_{\mathrm{res}}$ is the number of resolution states per lag interval.
This is Johnson--Nyquist noise from first principles.

\textit{Step 3: Spectrum reconstruction.}
For Orbitrap and FT-ICR, the shader applies the discrete Fourier transform
to the image current time series (stored in $\mathcal{T}_5$ across pixels
representing time steps):
\begin{equation}
  \hat{S}(\omega) = \sum_{n=0}^{N-1} s(n\Delta t)\,e^{-2\pi i \omega n/N}.
\end{equation}
Each frequency $\omega$ corresponds to an $m/z$ value via the analyser
scaling law (Eqs.~\eqref{eq:ch21-orbitrap}--\eqref{eq:ch21-fticr}).  The
GPU executes this as a parallel FFT natively---each pixel computes one
frequency bin simultaneously.

\paragraph{Output.}
Texture $\mathcal{T}_6$: the mass spectrum.  Each pixel stores $(m/z, I)$,
the complete output of the mass spectrometric observation.

\begin{consequence}{Signal Processing as Categorical State Flux}{p6-signal}
  Pass~6 IS the signal processing chain.  The categorical state change at
  the detector propagates at $v_{\mathrm{signal}} \approx 2\times 10^8
  \,\mathrm{m/s}$---not at the drift velocity of charge carriers
  (${\sim}10^{-4}\,\mathrm{m/s}$).  The $10^{12}$ velocity ratio proves
  that the ``current'' in the amplifier chain is categorical state
  propagation, not charge transport.  Noise is partition entropy from lag
  accumulation.  The Fourier transform is a partition topology readout.
\end{consequence}

\section{Why Additive Blending Replaces the Accumulation Loop}
\label{sec:ch22-blending}
%==============================================================================

In the CPU reference implementation, accumulated ion density fields are computed
by a sequential loop:
\begin{equation}
  \mathrm{canvas}[\mathbf{x}] \mathrel{+}= W_i(\mathbf{x}), \qquad
  i = 1, \ldots, N.
\end{equation}
This requires $N\times H\times W$ sequential floating-point additions.
For $N = 50$ ions on a $512^2$ grid: $50 \times 262{,}144 = 1.3\times 10^7$
operations.

The GPU replaces this with additive blending hardware:

\begin{theorem}[Blending Equivalence]
\label{thm:ch22-blending}
  GPU additive blending (\texttt{gl.blendFunc(ONE, ONE)}) with $N$ draw calls
  produces the same accumulated field as the sequential loop over $N$ ions
  and $H\times W$ pixels, using $O(N)$ effective operations versus
  $O(N\times H\times W)$ sequential operations.  Speedup: $H\times W =
  262{,}144\times$ for a $512^2$ grid.
\end{theorem}

\begin{proof}
  Additive blending computes $\mathrm{framebuffer}[\mathbf{x}]\mathrel{+}=
  \mathrm{fragment}[\mathbf{x}]$ for all pixels $\mathbf{x}$ simultaneously.
  For $N$ ions, the GPU executes $N$ draw calls $\times$ 1 parallel
  evaluation $= O(N)$ effective operations.  The sequential CPU loop
  executes $N\times H\times W = O(N\cdot HW)$ operations.  Speedup factor
  is $HW$.
\end{proof}

The deeper interpretation is partition-theoretic.  Each draw call renders one
ion's contribution to the partition depth field.  Blending accumulates these
contributions exactly as the partition sum
$\Depth_{\mathrm{total}} = \sum_i \Depth_i$
dictates.  The GPU blending hardware IS performing the partition summation.
It is not ``accelerating'' an approximation; it is executing the partition
operation natively.

\paragraph{Benchmarks.}
CPU reference (50 ions, $512^2$): 1{,}166~ms.  GPU estimate: ${\sim}5$~ms.
Speedup: $233\times$.  CPU reference (10 ions, $64^2$): 8.5~ms.  GPU: 1.0~ms.
Speedup: $8\times$.  Both within the range predicted by Theorem~\ref{thm:ch22-blending}.

\section{$O(1)$ Memory Architecture}
\label{sec:ch22-memory}
%==============================================================================

\subsection{The Traditional Storage Problem}

Traditional spectral database approaches store $N$ compounds, each with
$d$-dimensional spectral data: $O(N\times d)$ memory.  For PubChem
($N \approx 10^8$ compounds, $d = 1024$ spectral features): $\sim 10^{11}$
values, approximately 410~GB---exceeding any single GPU memory by two orders
of magnitude.

\subsection{Observation Is Free to Re-perform}

\begin{theorem}[Observation Re-performability]
\label{thm:ch22-reperform}
  A GPU partition observation can be re-performed in $O(|V|\times K)$ time,
  where $|V|$ is the number of ions and $K = 14$ is the S-entropy
  dimensionality.  For $|V| = 10^3$ ions: $14{,}000$ operations at
  $10^9\,\mathrm{ops/s}$ $= 14\,\mu$s.  Storing observations is therefore
  redundant.
\end{theorem}

\begin{proof}
  The observation apparatus (six shader programs) persists on the GPU.
  The input for each compound is its S-entropy coordinates: $O(K)$ numbers.
  Re-observation requires only setting $O(K)$ uniform values and issuing
  six draw calls.  The observation is deterministically reproducible because
  partition synthesis is deterministic (Partition Determinism,
  Chapter~\ref{ch:triple}).  No intermediate state need be stored.
\end{proof}

\subsection{Streaming Architecture}

\begin{protocol}[Streaming Observation Protocol]
\label{prot:ch22-streaming}
  Processing a database of $N$ compounds at $O(1)$ memory:
  \begin{enumerate}
    \item Load batch of $B$ S-entropy coordinate sets
      ($O(B\times K)$ CPU memory).
    \item Observe each compound via Pass~1 (reuse texture $\mathcal{T}_1$).
    \item Observe interference with query via Pass~6 (reuse $\mathcal{T}_6$).
    \item Extract quality metrics via GPU readback ($O(1)$ per compound).
    \item Discard batch; load next.
  \end{enumerate}
  Total GPU memory: shaders (${\sim}10\,\mathrm{MB}$) + 6 textures
